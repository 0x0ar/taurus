# Niri

Configuration is stored in `~/.config/niri`. The main file is `config.kdl`, which includes files from the `config/` directory:

- `env.kdl` - environment variables
- `input.kdl` - keyboard layout, touchpad, and mouse settings
- `output.kdl` - display and resolution setup
- `layout.kdl` - gaps, column width, and border settings
- `autostart.kdl` - startup processes
- `keybinds.kdl` - keybindings for compositor actions and shell controls
- `focus-colors.kdl` - focus ring colors, generated by Taurus from the current theme (do not edit)

## Autostart

The shell daemon and clipboard history are launched from `config/autostart.kdl`:

```kdl
spawn-at-startup "bash" "-c" "wl-paste --type text --watch cliphist store"
spawn-at-startup "bash" "-c" "wl-paste --type image --watch cliphist store"
spawn-at-startup "taurusd" "start"
```

`taurusd start` also starts the [audio engine](/audio).

## Keybindings

Shell overlays and controls are bound in `config/keybinds.kdl` using `spawn "taurus" "msg" "toggle" "<module>"`:

- `launcher` - application launcher (`Mod+D`)
- `system` - system control panel (`Mod+B`)
- `clipboard` - clipboard history (`Mod+C`)
- `music` - media player (`Mod+M`)
- `wallpaper` - wallpaper selector (`Mod+W`)
- `calendar` - calendar popout (`Mod+S`)
- `network` - network connections (`Mod+N`)
- `volume` - audio popout (`Mod+V`)
- `settings` - cheat sheet for keybindings (`Mod+H`)

Workspace switching is routed through the shell to update bar indicators:

```kdl
Mod+1 { spawn "taurus" "msg" "workspace" "1"; }
Mod+2 { spawn "taurus" "msg" "workspace" "2"; }
// ...
Mod+Shift+1 { spawn "taurus" "msg" "workspace" "1" "move"; }
```

Mouse wheel (with `Mod`): the main wheel switches workspaces and the thumb wheel (for example on an MX Master) moves between columns. Both stop at the edges. Remove `Mod+` from those lines in `keybinds.kdl` to use the wheel alone.

The focus ring follows the theme: every time Matugen or a preset changes the colors, Taurus rewrites `config/focus-colors.kdl` (active ring = primary color) and niri reloads it. Older configs get the `include "config/focus-colors.kdl"` line added after `layout.kdl` automatically.

Quick utility actions:
- Lock screen: `Mod+L { spawn "taurus" "lock"; }`
- Reload shell: `Mod+R { spawn "taurus" "reload"; }`
- Bar autohide: `Mod+A { spawn "taurus" "msg" "bar" "autohide"; }`
- Screenshots: `Print { spawn "taurus" "screenshot"; }` (add `--edit` or `--full`)
- Brightness: `XF86MonBrightnessDown` and `XF86MonBrightnessUp`
- Volume: `XF86AudioLowerVolume`, `XF86AudioRaiseVolume`, and `XF86AudioMute`

## Screen resolution, refresh rate, VRR and rotation

**Settings → Display → General** shows, for each screen, a resolution and a refresh rate list built from the modes the screen reports, a **Variable refresh rate (VRR)** switch (only when the screen supports it) and a rotation list.

A change is applied at once, then Taurus asks you to keep it. If you do not confirm within 15 seconds (for example because the screen went black), it goes back to what it was. **Keep** saves the screen's mode, scale, rotation and VRR in `~/.config/niri/config/output.kdl`, between two comment lines that mark the block as Taurus's. If that file already has an `output "NAME"` block of your own, Taurus does not write a second one: it tells you to edit yours by hand.

VRR has three modes: **Off**, **Always on** (`variable-refresh-rate`) and **Only in games** (`variable-refresh-rate on-demand=true`). In the games mode the screen only uses VRR while a game window is shown, so Taurus adds a `window-rule` to `output.kdl`, between two comment lines, that matches Steam games (`steam_app_*`) and `gamescope`. Add your own `match` lines inside that block for other launchers; Taurus never rewrites the block once it exists.
